## Import and state

Choose **Recorded runs**, then **Choose recorded-run bundle**, and select the
harness-exported ZIP. All processing is local to the tab. A cancellable worker
checks ZIP structure, actual decompression bounds, CRC, SHA-256, canonical UTF-8
JCS bytes, exact schema, profiles, source ordering, evidence and count reconciliation
before returning any records. Imported data never enters `StudioClient`, workflow
definitions, owner commands, or the live run projection. Rendering creates no links
from imported fields and never activates HTML or retrieves artifacts.
The digest-only action/provider-request identity rule is enforced for manifest
identities and every record before profile branching. Known STS2 payloads and
diagnostics must come from their specified source stream. Optional profiles use
the owner-pinned grammar, including uppercase, colon and plus. Generic identity
tuple equality remains valid and implies no relationship by itself.

Timeline and accounting are separate authoritative files. The view preserves exact
decimal nanosecond/sequence strings and owning identity namespaces. Source stream,
ordinal and subrecord order is presentation order, not cross-stream causality.
Unknown optional profiles preserve only their admitted opaque digest metadata.
Unknown action receipts remain unknown; completed provider execution cannot imply
gameplay success. Episode failure does not assert authoritative game defeat.

The same semantic digest re-import is idempotent. A different recording or revision
is staged for explicit Replace/Keep choice; no evidence is merged. Failed or cancelled
imports retain the previous validated recording. Clear removes it from tab state.
No persistent recording storage is claimed. Workflow fixture and live-owner modes
remain separate from recorded inspection.

## Limits and implementation

The decoder enforces the candidate's 16 MiB compressed, 32 MiB extracted, 16 MiB
per-data-entry, 256 KiB manifest, 1 MiB omissions, 32 ZIP entries, 64 KiB record,
25,000 records, 32-level nesting and 100,000 JSON-value limits. ZIP must use the
candidate's classic regular-file subset (STORED or DEFLATE, no links, descriptors,
comments, extras, hidden bytes, duplicate paths or overlapping extents).
Decompression streams enforce actual output size incrementally. Import runs in a
worker that can be terminated immediately; each timeline page has at most 100
rows, one expanded row, and bounded text previews. Accounting is paginated too.
The worker caps file size before reading its array buffer. Both NDJSON entries pass
one shared record/line preflight before any record JSON is materialized. The parse
loop retains its own shared limit; oversized input is rejected before creating a
byte view. Dispositions require truthful reason/class/source and final-tail pairs.

`packages/recording` owns independent validation. AJV validates the exact copied
JSON Schema; Studio's JCS writer is independent from the existing workflow semantic
canonicalizer. SHA-256 uses `@noble/hashes`, allowing hashing on the authorized HTTP
LAN preview where `crypto.subtle` may be unavailable. No runtime validator code is
imported from protocol. Protocol's golden/invalid ZIPs establish shared acceptance.

## CLI and reproducible checks

Use Node 24.16.0 and npm 11.13.0 from the repository root:

```sh
npm ci --ignore-scripts
npm run lint
npm test
npm run build
node tools/inspect-recording.mjs /absolute/path/to/recording.zip
node tools/check-recorded-summary.mjs /path/to/protocol-worktree /absolute/path/to/recording.zip
node tools/check-recorded-privacy.mjs /path/to/protocol-worktree
```

To reproduce the exact candidate3 snapshot after preserving existing proofs:

```sh
node tools/snapshot-recorded-candidate.mjs /path/to/protocol-worktree recorded-run-bundle-v1-candidate3 580c1cf3be4bb3e4eb37b9acd9166808b7386b0eb84286cc0798a0d88e35bb35 a6c32127290f4d5e670d8863f97a74a7b8e3e411e735d81394b51fe1578b4eb6
```

This verifies the supplied schema/inventory pins and all inventoried bytes before
writing the active snapshot. Run the privacy probe next to regenerate its separate
synthetic vectors for that wire version.

The inspect CLI prints one JSON summary to stdout and exits 0 only after all
validation passes. Errors produce fixed diagnostic codes to stderr and exit 1.
The CLI uses Vite's local module loader for the identical browser decoder; it
opens no HTTP listener. Summary fields exactly match protocol's validator:
`valid`, `semantic_digest`, `recording_identity`, `evidence`, `completeness`,
`streams`, `event_records`, `accounting_records`, `unsupported_records`.

The local audited Chromium setup requires font configuration and both extracted
library roots. These environment paths are machine-specific, not deployable assets:

```sh
FONTCONFIG_FILE=/tmp/ascension-browser-audit/fonts.conf \
LD_LIBRARY_PATH=/tmp/ascension-browser-libs/root-20260910/usr/lib/x86_64-linux-gnu:/tmp/ascension-browser-libs/root-20260910/lib/x86_64-linux-gnu \
npm run test:recorded-browser
```

This builds and serves only `127.0.0.1:4181`, runs Chromium file selection, failures,
re-import/replacement, navigation, accounting/observation, 25,000-record pagination
and dark designer contrast checks, then stops the server. Screenshots and JSON
evidence are under `docs/evidence/recorded-run-local/`. These are local synthetic
checks; coordinator owns actual Train export, deployed LAN verification and release
admission. No host deployment, provider execution or game launch is performed here.
