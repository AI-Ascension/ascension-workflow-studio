# 01 — Scope and Phase-1 admission

## Assumption and evidence boundary

The user explicitly assumes Phase 1 is implemented. Plan Phase 2 on that basis.
Do not redo the strict/dynamic scheduler, journal, action kernel, gateway fencing,
CLI, or replay engine. At execution, discover actual exported contracts so the
browser integrates with the implementation rather than the earlier proposal.

## Required dependency inventory

For each boundary record producer repository/head, artifact schema/profile,
artifact SHA-256, consumers, test command, actual result, and support level:

| Surface | Phase-2 use |
|---|---|
| Definition schema/compiler | Import/export, typed graph authoring, definitive validation/digests |
| Node and type registry | Palette, forms, ports, protected composites, capability requirements |
| Policy and capabilities | Permitted models/operations/budgets, unavailable explanations |
| Workflow registry | Immutable revisions, templates, resolution of pinned subworkflows |
| Draft/layout persistence | Incomplete document saves, concurrency, durable restoration |
| Status/snapshot and events | Live inspection, invocation identity, uncertainty, stream recovery |
| Commands and command lookup | Start/pause/resume/step/cancel and lost-response resolution |
| Historical artifacts/replay | Offline inspection, divergence and approved decision projections |
| Authentication/authorization | Browser pairing/session, resource scopes and revocation |

Classify each as existing-and-admitted, additive-owner-change, capability-gated,
or blocked. Record actual operation names/routes rather than copying example URLs.
Resolve old/new schema differences explicitly; no automatic field stripping.

## Small owner additions allowed

A node registry read projection, authoring draft persistence, conditional publish,
command outcome lookup, browser session adapter, or snapshot watermark may not
have been required verbatim by Phase 1. Add the minimum necessary contract in
`sts2-harness`, version it, test old clients, and export a reviewed inert artifact.
The Studio may not privately infer missing run authority or implement a fallback
scheduler. No new gameplay verbs are required by Phase 2.

## Explicit exclusions

No cloud multi-tenant service, billing, plugin marketplace, arbitrary scripts,
browser-agent execution, AI image creation, marketing overhaul, game asset
redistribution, desktop shell, automatic live graph migration, CRDT collaboration,
new game integrations, new model provider, or ground-up map visualizer. Concurrent
edit conflict handling is required; real-time multi-user cursors are not.

Author strict workflows and declared adaptive regions. Do not support editing a
currently executing dynamic plan in place. A modified strategy is a new draft/
definition revision for a later run. Existing safe-point controls may be surfaced
only if actually admitted; they are not a reason to expand runtime authority.

## Dependency gate behavior

A missing actual Phase-1 environment blocks real integration evidence, not all
frontend progress. Use explicit synthetic fixtures with a visible fixture badge,
write contract tests and adapters, then leave the real integration gate unpassed.
Do not count a fixture server as Phase 1, relabel a stub as production, or remove
the blocked requirement. A conflicting current normative contract needs an ADR,
not a silent override by these seed specifications.
